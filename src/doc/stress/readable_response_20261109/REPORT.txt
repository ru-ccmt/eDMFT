Readable dmft2 stress-response output — 9 November 2026

Requested interface
case.outputdmf2_response is a readable, live response journal and numerical
summary. Both x_dmft.py and run_dmft.py use it through dmft2_step.py.
run_dmft.py imports scf from scf_merge.py. That merger and merge_scf.py use
stress_response_publish.py, preserving the existing final-pass-only policy.
No separate run_dmftp.py exists in the inspected source/installation.

During a calculation
The launcher reports ordinary dmft2, native central preparation, the actual
Python/native MPI commands, and the response workspace. MPI rank zero appends
flushed setup, radial-search, adjoint-action, source and contraction messages.
A failed or deferred step is explicitly identified; a new tracked step starts
a fresh latest-run journal. Completed runs archive the journal inside their
response workspace as outputdmf2_response.txt. Publication updates that archive.

Numerical sections
1. Complete tensor and both mean-tensile/compression-positive sign conventions.
2. Explicit functional derivatives: lattice geometry, explicit lattice
   potential, core and density terms, and the radial-energy-search completion.
   The latter is explicit_Ry minus the fixed-energy pieces in report.json.
   Screened induced contributions and total derivatives are shown separately.
   These are Ry per unit strain, with every strain matrix defined.
3. Convergence residuals, bands/k points/ranks, ensemble and timings.
4. After successful SCF assembly: physical +D, -V, -C contributions, original
   total, net response correction, and final tensor in GPa. The calculation's
   actual current iteration is used, never its accumulated SCF history.
5. Paths to immutable JSON records, logs, snapshots and native exports.

The GPa factor matches the response JSON driver. WIEN mixer's historical factor
is different by approximately 0.6 ppm; this has no effect on publication, which
uses the unchanged Ry/Bohr^3 tensor. The response does not modify case.scf2.
Publication marks the SCF handoff; manual mixer completion is not tracked by
this journal. case.scfm remains the mixer output.

Historical report generation
  python ~/dbin/stress_response_summary.py FeSe
rebuilds the text output from saved status/report/SCF records. It verifies the
report hash and locates the last SCF block with that reference ID. It holds
the normal launcher lock, preventing a concurrent run from losing its journal.
It does not revalidate a historical result for reuse on a changed charge.
It changes no calculation input, SCF, status JSON or numerical report.

Validation
315 component tests pass, including both merger paths, unchanged input tensors,
publication signs, old-SCF-history isolation, report hash rejection, explicit
versus induced terms, shear display, reporting I/O failure, deferred/failed
status and concurrent-run preservation. The existing native fixed-column stress
publication tests still pass. No new full material solve is needed: only
reporting and progress hooks change. A saved FeSe result was used to inspect
the complete text layout and numerical decomposition before installation.

Installation
Six shared Python helpers and three source test files. Source/dbin copies are
hash-checked against the staged originals before installation and against the
new copies afterwards. Backups and the patch are kept with this checkpoint.
