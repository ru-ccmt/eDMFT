Activate the normal Python/WIEN environment:
  source ~/activate

Run the complete charge response from archived input snapshots:
  ~/dbin/wien_frozen_sigma_response.py SrVO3_response_config.json
  ~/dbin/wien_frozen_sigma_response.py FeSe_response_config.json
The configured workspace must not exist. Adjust it to repeat a run. This
produces response.density and two physical endpoint potentials. It does not
modify the input calculation or add a stress tensor to mixer automatically.
The current WIEN LAPW1 must include the existing fixed-G marker support.

Repeat the saved hydrostatic projector-stress contraction:
  ~/dbin/frozen_sigma_projector_stress.py --matrices SrVO3/projector_correction_matrices.npz --analytic 5.67688415 --numeric 2.933836407 --output /private/tmp/SrVO3_response_correction.json
  ~/dbin/frozen_sigma_projector_stress.py --matrices FeSe/projector_correction_matrices.npz --analytic -0.1164916715 --numeric -1.0491512951 --output /private/tmp/FeSe_response_correction.json

The band-operator projection from a NEW pair of endpoint potentials is still
the diagnostic potential probe, described in the PDF and research_drivers.
It includes material advection and MT/interstitial partition corrections;
raw VNS subtraction is insufficient. The NPZ arrays here already include it.

Native hooks are available in ~/dbin/dmft2_response, separately from the
ordinary production dmft2. The repository contains all source changes and
all installed Python helpers. See INSTALL_MANIFEST.json and native_response.patch.
